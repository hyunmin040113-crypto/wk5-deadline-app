# 틈 · 이동 시간을 내 시간으로

출퇴근 이동 중 원하는 활동을 선택해 시작하고, 환승이나 이탈로 잠시 멈춰도 마지막 지점(RETURN POINT)에서 다시 이어가도록 설계한 모바일 웹 UX 프로토타입입니다. 핵심 흐름은 활동 선택 → 시작 → 중단 → 복귀 → 완료입니다.

## 프로젝트 소개

PRD와 사용자 시나리오에서 출발해, 이동 시간과 환승 때문에 원하는 활동을 시작하거나 이어가기 어려운 문제를 다룹니다. 프로토타입은 실제 서비스 연동보다 사용자가 이동 중 활동을 선택하고 다시 돌아오는 경험을 살펴볼 수 있도록 구성되어 있습니다.

## 사용한 도구와 기술

- React, TypeScript, Vite
- Lucide React 아이콘
- 브라우저 LocalStorage (활동 설정, 진행 상태, 기록 저장)
- pnpm lockfile로 의존성 버전 관리
- Codex: 화면 코드 수정, 사용자 피드백 반영, 대화형 브라우저 미리보기 확인
- GitHub: 저장소 생성과 소스·문서 버전 관리
- Windows 파일 탐색기와 브라우저 개발자 도구: 프로젝트 파일 관리와 로컬 상태 초기화

외부 교통 정보, 밀리의 서재, 넷플릭스 등 실제 서비스를 연동하는 API는 사용하지 않았습니다. 화면에 표시되는 콘텐츠와 이동 정보는 프로토타입용 예시입니다.

## 핵심 기능

- 출근길·퇴근길 활동 선택과 연결 서비스 설정
- 도보, 승강장 대기, 활동, 환승 안내, 환승, RETURN POINT, 완료로 이어지는 시나리오
- 활동 중 다른 앱으로 이탈했을 때 원래 활동을 상기시키는 퇴근길 흐름
- 활동의 마지막 진행 지점 표시와 복귀 경험
- 완료 시간·진행 범위 및 활동 기록 보기
- 시나리오 시뮬레이터로 실제 시간을 기다리지 않고 다음 상황 진행
- 설정과 완료 기록을 브라우저 LocalStorage에 유지

## 실행 방법

Node.js 20 이상 환경에서 프로젝트 폴더에서 실행합니다.

```bash
pnpm install
pnpm dev
```

배포용 빌드는 `pnpm build`, 빌드 미리보기는 `pnpm preview`로 실행합니다. npm을 사용하는 경우에도 `npm install`, `npm run dev` 등 `package.json`의 스크립트를 사용할 수 있습니다.

## 시나리오 체험

- 오늘 화면에서 출근길 또는 퇴근길 활동을 고릅니다.
- 화면 흐름에 따라 활동 시작, 환승 전 안내, 환승, RETURN POINT, 완료 기록을 체험합니다.
- 퇴근길 흐름에서는 `다른 앱을 열었어요`를 눌러 이탈 상기와 복귀 제안을 확인합니다.
- 화면 오른쪽 시뮬레이터의 `다음 상황으로` 버튼을 누르면 흐름을 진행할 수 있습니다. 모바일에서는 우측 `TEST` 탭 또는 상단 메뉴 버튼으로 시뮬레이터를 엽니다.

## 프로젝트 구조


## 프롬프트와 작업 회고

이 절은 실제 대화에서 나온 요청과 수정 과정을 정리한 회고입니다. 따옴표 안의 요청은 대화의 취지를 보존해 짧게 요약했으며, 원문 전체를 그대로 옮긴 것은 아닙니다.

### 요청을 구체화하며 진행한 방식

처음부터 앱 전체를 한 번에 다시 만들기보다, 사용자가 브라우저에서 선택한 화면 요소를 기준으로 문구·배치·동작을 한 항목씩 고쳤습니다. 요청이 분명한 경우에는 화면을 보고 바로 수정했고, 화면 상태에 따라 결과가 달라지는 뒤로 가기 동작은 실제 시나리오 흐름을 코드에 연결했습니다.

대화에서 다룬 대표 요청은 다음과 같습니다.

- **출근 흐름의 시작점:** “출근 시나리오상에서 처음 화면이 홈 화면이 되게” 요청해 출근 시나리오 첫 화면을 홈으로 맞췄습니다.
- **홈 인사말:** “좋은 아침이에요 / 출근길을 시작해볼까요?”로 문구를 바꾸고, 가능한 범위에서 글자를 크게 하면서 두 줄로 보이게 조정했습니다.
- **이동 중 화면:** 역까지 남은 시간과 도착 후 이어읽기 안내의 줄바꿈·글자 크기를 모바일 폭에 맞추고, 이동 중 장식 일러스트를 제거했습니다.
- **읽기 진행 카드:** 이어읽기 위치와 전체 분량 퍼센트를 한 카드에 담고, 얇은 진행 막대를 추가했습니다. 이어서 참고 레이아웃에 맞춰 표지와 밀리의 서재 아이콘도 카드 디자인에 반영했습니다.
- **승강장 화면:** 제목을 “열차 도착까지 3분 남았어요!”로 바꾸고, 열차 정보의 아이콘과 텍스트를 정렬했습니다.
- **활동 화면:** 책 표지를 책 목업 안에 배치하고, “다른 앱을 열었어요”를 “활동 잠시 멈추기”로 변경했습니다.
- **복귀 지점 화면:** 제목을 “아까 읽던 책, 이어서 읽어볼까요?”로 두 줄 배치하고, 설명과 하단 안내 중 요청한 문장을 삭제했습니다.
- **완료 화면:** “내가 고른 활동으로 채운 이동 시간, / 오늘도 수고했어요.”로 문장과 줄바꿈을 정리하고 상단 화살표가 홈으로 가게 했습니다.
- **홈 헤더:** 작은 화면 제목 줄을 없애고 상단 구성요소를 바꿨다가, 최종 피드백에 따라 중앙의 ‘홈’ 글자도 다시 제거했습니다.

### 효과적이었던 요청 방식

이번 작업에서는 다음처럼 구체적인 정보를 주었을 때 수정 방향이 가장 분명했습니다.

1. **화면과 대상 지정:** 홈, 승강장, 활동, 복귀 지점, 완료 화면 중 어디인지 밝히고, 바꿀 문구나 버튼을 지정합니다.
2. **원하는 결과를 그대로 제시:** “없애줘”처럼 삭제할지, “A를 B로”처럼 교체할지 명시합니다. 문구의 줄바꿈도 원하는 줄 단위로 적으면 결과를 맞추기 쉽습니다.
3. **동작의 목적 설명:** “뒤로 가기”만 말하는 것보다 “출근 시나리오상 바로 전 화면으로 돌아가게”처럼 어떤 흐름으로 돌아갈지 설명하면 구현이 정확해집니다.
4. **화면 크기나 우선순위 제시:** “모바일에서 한 줄로 가능한 가장 큰 크기”처럼 조건을 주면 단순한 픽셀 값보다 다양한 화면 폭에 맞추기 쉽습니다.
5. **참고 이미지와 적용 범위 제공:** 원하는 카드 구조, 표지 위치, 아이콘 위치를 이미지에서 짚어주면 디자인 의도를 파악하기 좋습니다. 정확한 이미지 자산을 화면에 쓰려면 이미지 파일도 프로젝트에 포함되어야 합니다.

### 실제로 다시 조정한 부분과 배운 점

- **헤더의 ‘홈’ 제목:** 처음에는 홈 화면 상단 중앙에 ‘홈’을 넣었지만, 실제 미리보기에서 사용자가 원한 최종 모습은 글자 없는 헤더였습니다. 처음 요청을 반영한 뒤 화면을 확인하면서 최종 선호가 더 구체화된 사례입니다. 화면 일부를 바꾼 뒤 실제 뷰포트에서 확인하는 과정이 필요했습니다.
- **뒤로 가기 버튼:** 몇몇 화면에서는 뒤로 가기 버튼을 제거해 달라는 요청이 있었지만, 이후에는 시나리오상 직전 화면으로 가도록 요청이 구체화됐습니다. 버튼을 무조건 홈으로 보내지 않고, 승강장·복귀 지점·홈에서 진입한 경우를 구분해 직전 화면 상태를 기억하게 수정했습니다.
- **복귀 안내 카드:** 홈 화면의 저장된 활동 안내는 한 카드만 제거하는 것으로 오해하지 않도록, 사용자가 지정한 상단 안내와 하단 재개 카드를 각각 확인해 둘 다 제거했습니다.
- **책 표지 이미지:** 참고로 첨부된 실제 표지 이미지는 프로젝트 파일로 제공되지 않아 그대로 불러올 수 없었습니다. 우선 앱 안의 벡터 표지 그림을 재사용해 썸네일을 구성했습니다. 이미지와 완전히 같은 결과가 필요하면 원본 이미지 파일을 저장소에 추가하고 그 경로를 연결해야 합니다.
- **문구 크기와 줄바꿈:** 일부 요청은 처음에 크기만 조정하면 문장이 예상과 다르게 두 줄로 나뉘었습니다. 이후 “해당 문구만”, “한 줄로 가능한 가장 크게”처럼 적용 범위와 줄바꿈 조건을 함께 지정해 의도에 맞췄습니다.

이 사례들은 단순히 한 번에 정답을 내기보다, 화면에서 대상을 지정하고 변경 결과를 확인한 뒤 피드백으로 세부 요구를 좁혀 간 반복 설계 과정입니다. 특히 문구 변경과 버튼 동작 변경을 구분해서 요청하고, 뒤로 가기처럼 흐름에 영향을 주는 기능은 이전 단계와 함께 설명하는 점을 배웠습니다.

### 다음 작업에서 사용할 요청 예시

> 승강장 화면의 상단 왼쪽 뒤로 가기 버튼을 누르면 홈으로 가지 말고, 이 출근 시나리오의 직전 단계인 ‘이동 중’ 화면으로 돌아가게 해줘. 다른 화면의 뒤로 가기 동작은 바꾸지 말고, 모바일 브라우저에서 눌러 확인해줘.

> 완료 화면 설명을 “내가 고른 활동으로 채운 이동 시간, / 오늘도 수고했어요.” 두 줄로 표시해줘. 완료 화면의 상단 화살표는 홈으로 이동하게 하고 다른 버튼은 유지해줘.

## 남은 한계

- 열차 도착 및 환승 알림, SNS 이탈 감지, 외부 앱 실행은 UI 시뮬레이션이며 교통정보나 외부 서비스와 연결되지 않습니다.
- 전자책·영상의 진행 지점과 활동 시간은 시나리오용 예시 데이터입니다. 실제 앱의 콘텐츠 상태를 읽거나 동기화하지 않습니다.
- 서비스는 로그인이나 백엔드 없이 동작하며 저장 데이터는 현재 브라우저의 LocalStorage에 한정됩니다.
- 실제 이동 환경에서의 알림 제공, 접근성, 다양한 경로와 혼잡도 대응은 검증이 더 필요합니다.

## 저장 데이터 초기화

브라우저 개발자 도구의 Application/Storage에서 현재 사이트의 `teum.activities`, `teum.logs`, `teum.run` 항목을 지우면 초기 데이터로 돌아갑니다.
